技术文档

BusTimeTable Cloud

基于 Fresh + Preact + TypeScript + Deno KV 的全栈班车时刻表管理与电子屏展示系统。从 Hono 静态架构迁移至边缘优先的现代全栈方案。

Fresh Preact TypeScript Deno KV Islands
01

现有项目

Hono 基础架构 + 静态 HTML 前端，手动路由与 JS 拼接。

核心原则
  • → 全栈 Fresh 架构，页面使用 Preact/TSX 组件化开发
  • → API 路由使用 Fresh 内置的 API 路由模式
  • → 交互使用 Fresh Islands 架构（选择性水合，零 JS 开销）
  • → 数据存储使用 Deno KV，无需外部数据库
  • → TypeScript 全栈（前后端类型共享）

Deno KV 数据设计

KV Key 命名规范
Key 命名 KV Schema 
// 站点
["stations", id]

// 线路
["routes", id]

// 班次
["schedules", routeId, time]

// 用户
["users", username]

// 系统配置
["settings", key]

类型定义（Station、Route、Schedule、User、Setting）保持原有设计不变，通过 lib/schema.ts 前后端共享。

Islands 策略

选择性水合，按需加载交互。

  • → 静态部分：布局、标题、页脚直接服务端渲染，零 JS
  • → 动态部分：时钟、倒计时、下拉交互 — Islands，按需水合
  • → 数据加载：Islands 内调用 API 路由
管理后台 /admin

使用 Preact 组件构建管理界面，所有操作通过 Fresh API 路由完成，JWT 存储在 localStorage。

  • AdminLogin.tsx — 登录表单
  • AdminDashboard.tsx — 站点/线路/班次统计
  • StationManager.tsx — 站点 CRUD
  • RouteManager.tsx — 线路 CRUD
  • ScheduleManager.tsx — 班次 CRUD + 批量导入

部署与开发

deno.json 配置
配置文件 JSON 
{
  "tasks": {
    "start": "deno run -A main.ts",
    "dev":   "deno run -A --watch main.ts dev",
    "seed":  "deno run -A scripts/seed.ts",
    "fmt":   "deno fmt",
    "lint":  "deno lint",
    "check": "deno check main.ts"
  },
  "compilerOptions": {
    "jsx": "precompile",
    "jsxImportSource": "preact"
  }
}
部署步骤
  1. 推送代码到 GitHub
  2. 在 dash.deno.com 创建项目，关联仓库
  3. Deno Deploy 自动检测 Fresh 项目并构建
  4. 首次部署后执行 deno task seed 初始化数据
  5. Deno KV 自动启用
本地开发
# 启动开发服务器
deno task dev

# 初始化数据
deno task seed

# 格式化 / 检查 / 类型检查
deno task fmt  deno task lint  deno task check

分阶段任务

阶段 0：Fresh 项目初始化
搭建 Fresh 项目骨架，API 路由就绪。
  • 0.1初始化 Fresh 项目 deno run -A https://deno.land/x/fresh/init.ts
  • 0.2配置 deno.json Fresh + Preact 依赖、tasks
  • 0.3创建 lib/kv.ts KV 连接封装
  • 0.4创建 lib/schema.ts 类型定义
  • 0.5创建 lib/auth.ts JWT + PBKDF2 工具函数
  • 0.6创建 _middleware.ts 认证 + 错误处理中间件
  • 0.7创建 API 路由骨架 所有 API 路由返回 501
阶段 1：数据层 + 展示 API
数据迁移与前端展示。
  • 1.1编写 seed.ts 从 JSON 迁移到 KV
  • 1.2实现展示 API display/stations、routes、schedules
  • 1.3实现电子屏页面 Preact 组件 + Islands
  • 1.4实现分享功能 复制链接 + URL 参数
  • 1.5实现自动刷新 30 秒轮询
阶段 2：管理后台
CRUD 管理界面。
  • 2.1实现登录 API POST /api/auth/login、GET /api/auth/me
  • 2.2实现站点 CRUD API
  • 2.3实现线路 CRUD API
  • 2.4实现班次 CRUD API
  • 2.5实现批量导入 API POST /api/routes/:id/schedules/batch
  • 2.6实现管理后台页面 Preact 管理面板组件
  • 2.7联调验证 所有 CRUD 可正常执行
阶段 3：部署上线
发布到 Deno Deploy。
  • 3.1推送 GitHub
  • 3.2创建 Deploy 项目 Deno Deploy 关联仓库
  • 3.3执行 seed 脚本 初始化数据
  • 3.4验证线上功能
  • 3.5绑定域名 可选
阶段 4：优化与完善
生产加固与体验优化。
  • 4.1添加 rate-limit API 限流
  • 4.2添加操作日志 KV 记录管理员操作
  • 4.3电子屏 PWA Service Worker 离线缓存
  • 4.4管理后台响应式 适配手机/平板
  • 4.5数据导出 JSON 导出
  • 4.6错误监控 Sentry 或自建上报
